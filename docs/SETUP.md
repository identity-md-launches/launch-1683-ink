## Upload planner

The Python program accepts explicit RPC, chain, owner and renderer values. It reads one fixed block snapshot, verifies the exact runtime against `out/InkRenderer.sol/InkRenderer.json`, verifies ownership, expected size/hash and every stored prefix byte, and emits JSON calldata. It has **no transaction sending or signing code**, no environment/key loading and no automatic locks. Example placeholders are names for future inputs, not deployable values:

```text
python3 tools/plan_upload.py --script ORIGINAL.js --renderer <actual-renderer> \
  --owner <actual-owner> --rpc-url <read-only-rpc> --chain-id <actual-chain-id>
```

Run `forge build` first. The artifact check deliberately rejects proxies or changed bytecode. A different unfinished upload is rejected unless the operator explicitly supplies `--restart`. `beginUpload(previousVersion, size, hash)` prevents a stale begin transaction from overwriting a newer session. `appendChunk(version, index, bytes)` rejects duplicates, gaps and stale sessions; resumption accepts arbitrary valid existing chunk boundaries within the 64-chunk bound. Restarting selects a new storage namespace instead of deleting old chunks, so a full prior upload cannot make restart exceed transaction gas limits. Old namespaces remain in historical contract storage and are not rendered. Every uploaded byte is hashed again before `lockScript(version, hash)`. Lock calldata is listed separately and should only be signed after re-reading the completed state. Preview lock binds to `previewHash` (`keccak256(abi.encode(mediaType, imageBytes))`, binding both MIME type and original image).

Uploads are limited to 64 chunks, each at most 8192 bytes; scripts to 131072 bytes and preview to 32768 bytes. These are storage/RPC bounds, not promises about the size or browser compatibility of the unsupplied original algorithm. The planner never runs the JavaScript. HTML passes raw `window.INK_INPUTS` and loads the exact script as base64; script strings containing `</script>` cannot escape into the host markup. CSP blocks outbound connections, remote images, external scripts and dynamic eval. An original algorithm needing those features requires further review; do not silently strip or replace it.

Metadata uses a base64 JSON data URI and a percent-encoded HTML data URI containing the base64 script. This avoids an unnecessary full-script encoding layer. The maximum script plus maximum preview costs approximately 45.7 million gas to read in the local isolated test; RPC/marketplace call limits may be lower. The maximum script lock costs approximately 9.3 million gas. Preview storage is a single transaction and large previews can be expensive. Choose actual sizes only after checking the target chain's transaction limits, RPC call budget and viewer behavior. Smaller original assets are preferable when possible without changing their content. No browser or marketplace compatibility of the absent original work is claimed.

## Position custody and fee collection

The official PositionManager holds the core liquidity position, and `InkLiquidity` owns its ERC721 token. The application exposes no generic execution, NFT transfer, NFT approval, ERC1271 signer, decrease-liquidity, burn, unwrap, rescue, fee-collection, or arbitrary recipient function. Neither its owner nor anyone else can collect LP fees. Fees therefore stay with the permanent position; this is intentional and must be understood before release. Hook fees are separate: they transfer immediately to the required INK sink / immutable IMD treasury.

Released INK is **pushed** by the vault. The liquidity contract prefunds the official PositionManager, mints a deterministic-amount single-sided position, settles from PositionManager's own balance, then sweeps only INK remainder back to itself, all atomically. There are no vault/liquidity/PositionManager ERC20 allowances. Integer liquidity rounding can leave dust in `InkLiquidity`; that dust also has no withdrawal path. Successful release moves the entire reserve into permanent custody, but does not claim every wei becomes liquidity. Tests at their ranges leave at most one wei; extreme ranges may leave more. Review chosen ranges and predicted rounding before funding.
